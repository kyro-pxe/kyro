Kyro v0.2.0 adds driver packs, armings that run out, progress and failure
reasons during an installation, and values per machine. Like v0.1.0-alpha
it was tested in virtual machines only (QEMU with OVMF, the Windows 11
Enterprise evaluation ISO). Nothing was tried on physical hardware.

## New

- **Driver packs.** Windows PE loads them, and Windows Setup carries them
  into the installed system, without a change to the ISO. `kyro driver add`
  takes any driver with `.inf` files; `kyro driver fetch` downloads
  `intel-rst` (Intel VMD, 12th to 15th generation), `intel-rst-11` and
  `virtio` from their makers with pinned checksums. Intel's driver needs
  Intel's license to be accepted (`--accept-license`); `install.sh` asks.
- **Armings run out**, after 24 hours by default (`arm_timeout`,
  `kyro arm --expires 2h`). A machine that boots later goes to its disk and
  is shown as `expired`.
- **Progress and failure reasons.** `kyro clients` shows whether Windows PE
  reached the install share, whether Setup started and how often it
  restarted the machine. A Setup error in Windows PE fails the client at
  once; a timeout says where the installation stopped.
- **Values per machine.** `{{var:hostname}}` in an answer file,
  `kyro arm --set hostname=PC-014` when arming. Values are deleted when the
  installation ends.
- **A profile that installs nothing by itself**:
  `kyro profile import --example-interactive` starts Setup and leaves every
  question to the screen, for checking drivers on a machine first.

## Upgrading from v0.1.0-alpha

Run the new `install.sh`; it keeps the configuration, images, profiles and
client records. Tested in a container, not on a real server.

- A client armed with v0.1.0-alpha stays armed until 24 hours after it was
  armed. Older armings count as run out: arm such a client again.
- `arm_timeout` is a new, optional setting; without it an arming lasts 24
  hours.
- The installer creates `/var/lib/kyro/drivers` and, from a terminal,
  offers Intel's storage driver. Without a terminal it skips the driver
  unless `--accept-intel-license` is given.

## Not tested

- Any physical machine, and any Intel VMD controller. The Intel driver was
  loaded in a virtual machine and arrived in the installed Windows; whether
  Setup then finds a disk behind a real VMD controller is unproven.
- The full end-to-end test was not run on this commit for lack of disk on
  the test server. It passed on 2026-11-16 on `e37ef4e`; what changed since
  and how it was checked is in
  [docs/v0.2.0.md](https://github.com/kyro-pxe/kyro/blob/v0.2.0/docs/v0.2.0.md).
